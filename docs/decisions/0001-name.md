# 0001. The name is Kanon

- **Status:** accepted
- **Date:** 2026-09-27

## Context

The workflow needed a name before it could have a repository of its own.

## Decision

**Kanon** (κανών): a measuring rod, a rule; the root of the English "canon". It names the product's promise: a standard that the work is checked against, and that an adopter accepts rather than configures.

## Alternatives considered

| Name | Why not |
|---|---|
| Tabernacle | Fitted the reference adopter's biblically named agent cast, but reads as a church app at first glance. |
| Telos | Crowded in exactly this space: an open-source AI context framework (~1.5k stars), an agent SDK, a blockchain, and Telos Corporation (a listed cybersecurity company, so a trademark risk). |
| Organon, Gnomon | Good meanings (Aristotle's rulebook for reasoning; a carpenter's set-square). Less immediate than Kanon. |
| Bezalel, Plumbline, Ordinance | Considered in the first round. |
| Tekton, Talos, Kairos | Already owned by well-known developer tools (a CNCF CI/CD project, a Linux distribution, another Linux distribution). |

## Consequences

- **Namespaces.** The `kanon` GitHub handle and the `kanonhq` organisation are taken, so the repository lives at `yedeya/kanon` for now. *(Kanon has since moved to the `yedeya-labs` organisation, and has been public there since 2026-09-30.)* `usekanon` and `getkanon` were free as organisation names on 2026-09-27. `kanon.sh` looked unregistered.
- **Agent names.** The reference adopter's agents have Hebrew names (Bezalel, Oholiab, Caleb, Thomas, Joshua), which fitted a Tabernacle name better than a Greek one. Whether Kanon ships a default named cast, or leaves names to each adopter, is decided in the rulebook's agents chapter.
