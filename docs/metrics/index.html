How these numbers are made

Where they come from

Each project's runs and work items, as Kanon's telemetry store holds them. The store's aggregate function reads the rows and answers estimates and counts, never a row. A project appears here only when its operator declared its figures publishable under a label of their choosing; the label is the only name this page holds.

What cost means

Cost is the API list price of the tokens a run reported, not what anyone paid. On a subscription the amount paid is a different number, and there is no translation to a subscription.

What each indicator does not claim

Cost per merged item
What the adopter paid: on a subscription that is a different number, and decision 1 forbids translating. Nor the spend on work that never merged (that is efficiency, §2.3), the Explorer's, Overseer's and digests' spend (shown as overhead, beside, never inside), or the cost of human time. Items with no run row at all (human-authored, §1.2) have no cost and are excluded, never counted as zero.
Yield
That unmerged spend was worthless: a bail that led to a split, or a PR closed because the plan changed, is still counted as not merged. Nor that the merged work was right (accuracy, §2.4).
Escape rates
That an item with no link had no defect. Detection needs a link someone made (§3.5), so the rate is a lower bound. Nor does approval measure correctness: a lenient reviewer raises it. That is why approval is never shown without the escape rate and the human-correction rate.

The detection gap

An escape is counted only when someone linked a revert or a fix to the item. A defect nobody linked is not counted, so the escape rates are lower bounds.

When a bail counts against yield

A merged item counts in the window it closes in. A run that stopped before opening a pull request counts only once its issue has had no run for 30 days, so that a run still being retried isn't counted as abandoned. So in a project's first 30 days, and for 30 days after any burst of such runs, yield reads high, and the "no PR" figure has few or no items, until they settle.

The release comparison

Each Kanon release with at least 10 merged items over the trend's span is compared with the one before it that has as many; an item is in the release its lanes pinned at its merge. A release with fewer items is listed, and pooled with no other. Cost is compared at equal size: a log-linear fit of log cost on log(1 + changed lines) and the release, which needs 10 merged items with a cost above zero and a diff size in each release, and gives the newer release's cost change in percent with its 95% interval. A release is a win only if that interval is entirely below zero and its quality holds within the margins, new minus old: yield's lower bound above −5.0 points and the 30-day escape rate's upper bound below +2.0 points (a bootstrap interval for yield from 20 items in each release, Newcombe's for escapes from 50). Cheaper without that is "cheaper, quality not shown to hold"; an interval entirely above zero is "dearer"; one that holds zero, "no measurable change". It says whether a release was cheaper at equal size, not that the release caused the difference: anything else that changed between the two releases' items, the model, a lane's configuration or the kind of work beyond its size, is read as the release's. A release whose items merged less than 30 days ago has too few matured items for the escape difference, so it reads "cheaper, quality not shown to hold" until they mature.

Bands, windows, samples and intervals

Band version 1. Each window is 28 days and ends at the start of the UTC day the page was computed. The figures are shown by band only when the band validity check finds cost rising with band (a Kendall τ-b interval above zero, from at least 10 items); otherwise they are pooled, with the band mix beside them.

Each figure shows its value, its 95% interval and its sample (n). Medians and p90s use an order-statistic interval, rates a Wilson interval, and yield a bootstrap of 2000 resamples with seed 1262571087. A figure from fewer items than its minimum shows "not enough data (N)": 10 for a median, 30 for a p90, 20 for approval and correction, 20 for yield, and 50 for an escape rate.
